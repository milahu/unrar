## 4. Two limitations worth knowing

- Detects password-buffer overflow.
- Preserves UnRAR's UTF-8 conversion path.

## 2. Important corrections for truly race-free behavior

The implementation above is substantially safer than the previous one, but there are still issues to address before shipping it as a production patch.

**First, `pselect()` does not solve every race in a multithreaded process.** Signal dispositions are process-wide. If another thread modifies the SIGINT disposition while the password reader is active, restoring `OldAction` could overwrite that change. A local function cannot safely coordinate with arbitrary signal-handling code without a shared synchronization policy.

**Second, `raise(SIGINT)` while SIGINT is blocked is not a complete substitute for the original signal behavior.** The signal remains pending until unblocked, and its handling depends on the original disposition and mask. The code's `_exit(130)` fallback can bypass the original handler.

**Third, terminal restoration can fail.** A production implementation must check `tcsetattr()` and avoid reporting successful cleanup when restoration failed.
